Email Assistant Backup

Email Assistant Backup is a private, user-authorised backup workflow for the Email Assistant application's PostgreSQL database. It is intended to create a recoverable copy in the account owner's own Google Drive.

How it works

  1. A scheduled or manually started GitHub Actions workflow exports the configured Neon PostgreSQL database.
  2. The database dump is encrypted on the temporary GitHub-hosted runner before upload, using AES-256-CBC with a PBKDF2-derived key (600,000 iterations).
  3. The encrypted backup and a SHA-256 checksum file are uploaded to a dedicated Google Drive folder selected by the account owner.
  4. The workflow retains the newest 16 backup files in that folder and removes older backup files according to its retention policy.
Data control: The Google account owner chooses the account and backup folder and grants access through Google's OAuth consent flow. The Drive folder is not made public by this application. The encryption passphrase is managed separately by the account owner and must not be shared with the application operator or placed in source code.

Google Drive access

The workflow requests the Google Drive drive.file permission. Its intended use is limited to backup files and the designated backup folder made available to this application. It does not need broad access to the user's entire Drive. The workflow uses the Drive API to upload backup files and manage its own backup retention.

Availability and limitations

Backups are stored in the user's Google Drive and count toward that account's storage quota. GitHub Actions scheduled runs are best-effort and may start later than their scheduled time. A successful upload alone does not prove that a backup can be restored; a separate restore test is required.
