Privacy Policy

Effective date: 20 November 2026

This policy describes how Email Assistant Backup uses Google user data when the account owner authorises the backup workflow. The workflow is intended for the private backup of the Email Assistant application's PostgreSQL database to the account owner's Google Drive.

Google data accessed

The application requests the Google Drive drive.file OAuth scope. This permission is used for Drive files that the application creates or that the user explicitly makes available to it. The workflow uses the Drive API to upload encrypted database backup files and checksum sidecars, and to inspect/manage those backup files for its retention policy. It is not designed to read Gmail, Google Contacts, Calendar, or unrelated Drive documents.

How Google data is used

  • To identify and access the dedicated backup folder selected for this application.
  • To upload the encrypted database dump and its SHA-256 checksum file.
  • To list backup-file metadata needed to retain the newest 16 backups and remove older backup files created for this backup workflow.

The application does not sell Google user data, use it for advertising, or use it to train general-purpose artificial intelligence or machine-learning models.

Encryption and storage

The database export is encrypted on a temporary GitHub-hosted Actions runner before it is uploaded to Google Drive. The documented workflow uses AES-256-CBC and PBKDF2 with 600,000 iterations. The encrypted backup and checksum are stored in the user's own Google Drive folder and count toward the user's Drive quota. The encryption passphrase is supplied as a GitHub Actions secret and should also be stored separately by the account owner in a password manager.

The workflow uses GitHub Actions to run the backup and GitHub repository secrets to hold the OAuth client credentials, refresh token, Drive folder ID, database connection string, and encryption passphrase. These credentials are not intended to be committed to source code or printed in logs. GitHub's and Google's own privacy and security practices also apply to data processed by their services.

Sharing and disclosure

Google Drive data is processed by Google Drive to provide the storage service. Backup execution and temporary processing are performed by GitHub Actions. The application does not intentionally disclose backup contents to other third parties. The Drive folder is intended to remain private to the account owner and people the owner separately chooses to share it with.

Retention and deletion

The workflow's configured retention policy keeps the newest 16 encrypted backup files in the designated folder and removes older backup files according to that policy. The account owner can also revoke the application's Google account access through their Google Account security settings and can delete backup files directly from Google Drive. Revoking access does not automatically delete files already stored in Drive.

Security limitations

No internet service or storage system can be guaranteed completely secure. The account owner is responsible for safeguarding the encryption passphrase and for periodically testing restoration of a backup into a separate, non-production database. A successful upload is not, by itself, proof that a backup is recoverable.

Changes to this policy

This policy may be updated when the backup workflow or its data practices change. The effective date above will be revised when material changes are made.

Contact

For questions about this backup workflow or this policy, contact the application operator using the support email displayed on the Email Assistant Backup OAuth consent screen in Google Cloud.
